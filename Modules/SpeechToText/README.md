# SpeechToText

Модуль превращает подготовленный аудиофайл в субтитры и тайминги отдельных слов. Здесь живут сами STT-провайдеры, выбор провайдера по настройкам и установка локальных моделей. Извлечение аудио из видео сюда не входит: модуль ожидает готовый файл в `TranscriptionInput.audioURL`.

## Как устроен пакет

Пакет разделён на два продукта:

- `SpeechToText` (`Sources/Api`) — публичный контракт. Его можно подключать, не зная, какой движок будет распознавать речь.
- `SpeechToTextImpl` (`Sources/Impl`) — локальные провайдеры, работа с моделями и преобразование сырых результатов в субтитры.

Главный контракт — `SpeechToTextProvider`. Он принимает `TranscriptionInput` и возвращает `TranscriptionResult`: субтитры, тайминги слов, определённый язык и длительность записи. `SpeechToTextProviderResolving` выбирает провайдер по `SpeechToTextProviderConfiguration`. Возможности движка описывает `SpeechToTextProviderCapabilities`, а ошибки наружу выходят как `SpeechToTextError`.

Для управления моделями есть отдельные протоколы `WhisperModelManaging` и `ParakeetModelManaging`. Благодаря этому экран настроек может проверять и загружать модели, не импортируя реализацию.

## Реализации

- `LocalWhisperSpeechToTextProvider` запускает локальный `whisper.cpp`, читает его JSON и собирает результат распознавания. Для более точных словесных таймингов умеет передавать DTW-настройки, а VAD подключает только при наличии модели.
- `ParakeetSpeechToTextProvider` работает через закреплённую версию `FluidAudio`. Длинное аудио режется на перекрывающиеся окна, результаты сводятся в одну шкалу времени, а большие пропуски могут заполняться словами из соседних окон. Если выбранный язык не поддерживается, провайдер может передать работу настроенному Whisper fallback.
- `MockSpeechToTextProvider` возвращает тестовый результат без настоящего распознавания.
- `ConfiguredSpeechToTextProviderResolver` и `SpeechToTextAssembly` собирают нужную реализацию по имени провайдера. Неизвестное имя сейчас ведёт к mock-провайдеру.
- `WhisperInstaller` на macOS ищет исполняемый файл Whisper и загружает выбранную модель; VAD считается необязательным. `ParakeetModelStore` хранит и загружает модели FluidAudio.

После ответа движка вспомогательные сервисы приводят данные к форме редактора: `WordTimingMerger` склеивает токены в слова, `WordTimingCueBuilder` строит реплики по паузам и границам текста, а `SubtitleSegmentationService` делит слишком длинные реплики и переиндексирует их.

## Обычный поток данных

1. Код выше по стеку готовит WAV и формирует конфигурацию провайдера.
2. Resolver возвращает Whisper, Parakeet или mock.
3. Провайдер сообщает прогресс через `TranscriptionProgressHandler`.
4. Сырой текст и тайминги превращаются в `[SubtitleSegment]` и `[WordTiming]`.
5. Готовый `TranscriptionResult` возвращается вызывающему коду. Сохранением проекта и анализом спикеров занимается уже `TranscriptionPipeline`.

## Тесты

Тесты проверяют аргументы запуска Whisper, модели и VAD, поддержку языков Parakeet, разбиение длинного аудио на окна и fallback. Отдельно покрыты склейка токенов, построение реплик и сегментация текста по пунктуации, длине и реальным словесным таймингам.

Запуск из корня репозитория:

```sh
swift test --package-path Modules/SpeechToText
```
