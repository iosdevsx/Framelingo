# DesignSystem

Здесь лежат общие визуальные детали Framelingo: небольшие SwiftUI-компоненты, цвета, отступы, радиусы, шрифты и несколько моделей, которыми экраны описывают свой вид. Модуль нужен, чтобы редакторы и остальные части приложения не собирали одни и те же контролы и значения заново.

## Что внутри

Основной код сейчас находится в публичном таргете `DesignSystem`:

- `DensityToggleView` переключает плотность редактора между `compact` и `comfy`;
- `LayoutSwitcherView` выбирает один из трёх вариантов раскладки субтитров и показывает для них схематичные иконки;
- `ProgressToastStack` и связанные модели отображают очередь, прогресс, успех и ошибку фоновых операций;
- `SurfacePanel` задаёт общий вид панели с материалом, отступом и рамкой;
- `DesignSpacing`, `DesignRadius`, `DesignTypography`, `DesignSystemPalette` и `AccentColorName` содержат переиспользуемые токены;
- `DesignSystemInteractions` передаёт через SwiftUI Environment платформенные действия вроде смены курсора и чтения модификаторов выделения.

Таргет `DesignSystemImpl` пока не добавляет реализацию: его единственный файл импортирует `DesignSystem`. Поэтому конкретные компоненты сейчас приходят из продукта `DesignSystem`, хотя пакет также публикует отдельный продукт `DesignSystemImpl`.

## Связь с приложением

Фичи используют модели `EditorDensity` и `SubtitleLayoutMode` как состояние своих экранов, а готовые views — как тонкий общий UI-слой. Палитра и платформенные взаимодействия приходят через Environment, поэтому конкретный экран не обязан знать, кто их настроил.

Пакет не зависит от бизнес-модулей и собирается для iOS 18 и macOS 15.

## Тесты

Тесты лежат в `Tests/DesignSystemImplTests`. Они проверяют разбор шестизначного RGB в `Color(hex:)`, отказ на некорректной строке и то, что `SurfacePanel` сохраняет конкретный тип вложенного SwiftUI-view без стирания типа.

```sh
swift test --package-path AppTarget/Modules/UI/DesignSystem
```
