# Settings

Модуль хранит пользовательские настройки Framelingo и даёт фичам единый способ читать их, обновлять и следить за результатом сохранения. В настройках сейчас находятся выбранные провайдеры, пути к FFmpeg и Whisper, параметры VAD, формат экспорта и вид субтитров.

## Что внутри

Публичный таргет `Settings` содержит:

- `AppSettings` — Codable-модель со значениями по умолчанию и совместимым чтением старых JSON, где новых полей ещё не было;
- `SettingsStore` — асинхронный контракт загрузки и сохранения;
- `SettingsManaging` — владелец текущего снимка настроек на `MainActor`;
- `SettingsSnapshot` и `SettingsPersistenceState` — сами настройки вместе с состоянием `idle`, `saving`, `saved` или понятной ошибкой;
- `SettingsAccess` — фасад на замыканиях, через который фичи могут пользоваться менеджером, не импортируя `SettingsImpl`.

`SettingsImpl` предоставляет `UserDefaultsSettingsStore`, `DefaultSettingsManager` и фабрики `SettingsAssembly`. Store кодирует всю модель в JSON и хранит её под ключом `Framelingo.AppSettings`. Manager сразу публикует новое значение для текущей сессии, последовательно сохраняет быстрые обновления и отдельно сообщает об ошибках загрузки или записи.

## Связь с соседними модулями

API зависит от `SpeechToText`, потому что значение Whisper-модели берётся из `WhisperModel`, и от `Subtitles`, где объявлен `ExportFormat`. UI настроек обычно получает `SettingsAccess`, редактирует локальную копию `AppSettings`, а затем отправляет её через `update(_:)`. Подписка `snapshots` позволяет показать сохранение или ошибку, не дублируя состояние хранилища в каждой фиче.

## Тесты

Тесты находятся в `Tests/SettingsImplTests` и проверяют:

- декодирование старых настроек и round-trip новых полей VAD;
- значения по умолчанию, повреждённый JSON и сохранение через отдельный suite `UserDefaults`;
- чтение старого fixture-файла;
- публикацию состояний менеджера, порядок быстрых сохранений и поведение при ошибках load/save.

```sh
swift test --package-path AppTarget/Modules/Core/Settings
```
