# SpeakerAnalysis

Модуль определяет, кто говорит в разные моменты записи, и связывает эти участки с субтитрами. Он умеет работать как с готовыми строками субтитров, так и с таймингами отдельных слов.

## Публичная часть

Таргет `SpeakerAnalysis` содержит модели и протоколы, которыми пользуются соседние модули:

- `SpeakerSegment` — временной участок с числовым id спикера и необязательной уверенностью;
- `WordTiming` — слово с началом, концом и уверенностью распознавания;
- `Speaker`, `SpeakerLabel` — сохраняемое описание и отображаемое имя спикера;
- `SubtitleAlignmentCue` — временная проекция строки для выравнивания; отдельно от основного массива субтитров она не хранится;
- `SubtitleAlignmentOptions` и `SubtitleCueWarning` — ограничения разбиения и предупреждения;
- `SpeakerDiarizationEngine` и `SubtitleAlignmentEngine` — контракты диаризации и выравнивания.

## Реализация

`SpeakerAnalysisImpl` даёт несколько вариантов, которые создаются через `SpeakerAnalysisAssembly`:

- `FluidAudioSpeakerDiarizationEngine` загружает или находит локальные модели FluidAudio, обрабатывает аудиофайл и переводит результат библиотеки в `[SpeakerSegment]`;
- mock-движок возвращает пустой результат и подходит для сценариев без реального анализа;
- cue-level alignment сохраняет существующие строки и назначает им спикера по наибольшему пересечению во времени;
- word-level alignment заново группирует слова по спикеру, паузам, длине и пунктуации, добавляет небольшие отступы к таймингам и убирает пересечения соседних строк;
- passthrough alignment возвращает входные строки без изменений.

FluidAudio закреплён на версии `0.14.1`. Модели лежат в стандартной директории библиотеки и при необходимости загружаются во время первого реального анализа. Прогресс можно получать через `DiarizationProgressHandler`.

## Поток данных

Обычно соседний медиасервис сначала готовит аудио. Движок диаризации превращает его в участки речи по спикерам. Затем alignment engine сопоставляет эти участки с существующими строками или с результатом распознавания по словам. Приложение переносит полученные id, тайминги и предупреждения обратно в свой единственный массив `SubtitleSegment`.

Модуль `Subtitles` зависит от публичного таргета `SpeakerAnalysis`, чтобы хранить speaker id и предупреждения и добавлять имена спикеров при экспорте.

## Тесты

Тесты лежат в `Tests/SpeakerAnalysisImplTests`. Они проверяют Codable-модели и стабильность стандартного списка спикеров, а также оба режима выравнивания: выбор спикера, предупреждения, разбиение на паузах и смене говорящего, сглаживание коротких выбросов, ограничения длины, перенос перевода и исправление пересекающихся таймингов. Загрузку моделей и реальный прогон FluidAudio тесты сейчас не выполняют.

```sh
swift test --package-path AppTarget/Modules/Core/SpeakerAnalysis
```
