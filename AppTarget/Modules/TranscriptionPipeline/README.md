# TranscriptionPipeline

Модуль связывает извлечение аудио, распознавание речи, анализ спикеров и сохранение проекта в один сценарий «транскрибировать проект». В отличие от `SpeechToText`, он знает о `Project`, его статусах и монтажной таймлинии.

## Как устроен пакет

- `TranscriptionPipeline` (`Sources/Api`) — запрос, конфигурация, фазы прогресса, результат, предупреждения, ошибки и протокол `TranscribingProject`.
- `TranscriptionPipelineImpl` (`Sources/Impl`) — сам сценарий и assembly с явными зависимостями.

Конфигурация объединяет выбранный путь к FFmpeg и `SpeechToTextProviderConfiguration`. Через события вызывающий код получает обновлённый `Project` и прогресс фаз: извлечение аудио, транскрипция, анализ спикеров и выравнивание субтитров.

## Как проходит транскрипция

1. Проект получает статус `extractingAudio`, публикуется и сохраняется.
2. Из монтажной таймлинии строится список source-клипов. Если виртуальных разрезов нет, извлекается весь звук; если есть — FFmpeg сразу склеивает только оставшиеся части.
3. Resolver выбирает STT-провайдер, а его прогресс прокидывается наружу. Результат записывается в `subtitles`, `wordTimings`, язык и, для полного исходника, длительность.
4. `SpeakerDiarizationEngine` анализирует тот же временный WAV, после чего `SubtitleAlignmentEngine` связывает реплики со спикерами. Если провайдер не дал словесных таймингов, они приближённо строятся из готовых реплик.
5. Для смонтированного проекта все временные коллекции ограничиваются итоговой длительностью. Проект получает статус `ready`, сохраняется, а временный WAV удаляется.

Ошибка анализа спикеров не отменяет успешную транскрипцию: результат возвращается с `speakerAnalysisUnavailable`. Ошибки FFmpeg, STT, сохранения и очистки файлов типизированы отдельно. Отмена не записывает проект как failed, но временный файл всё равно очищается.

## Зависимости и границы

`TranscriptionPipelineAssembly.makeTranscriber` принимает `ProjectRepository`, resolver STT, движки diarization/alignment и фабрику `FFmpegService`. Такой набор зависимостей здесь намеренный: пайплайн управляет последовательностью, а не реализует эти операции заново.

Модуль не содержит UI, конкретных STT-моделей, FFmpeg-команд или формата хранения проекта. Этим занимаются соответствующие нижележащие модули.

## Тесты

API-контракт проверяется отдельно от реализации. Сценарные тесты покрывают полный исходник и монтажную таймлинию, порядок событий и сохранений, передачу общей audio URL всем этапам, fallback без word timings, повторный запуск, отмену и сочетания ошибок операции, persistence и cleanup.

```sh
swift test --package-path AppTarget/Modules/TranscriptionPipeline
```
