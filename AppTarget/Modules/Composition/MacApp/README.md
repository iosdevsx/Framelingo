# MacApp

`MacApp` — точка, где из отдельных модулей собирается готовое macOS-приложение. Здесь выбираются реальные реализации хранилища, обработки видео, распознавания речи и экспорта, а затем из них строятся главный экран и команды меню.

Это один продуктовый модуль, а не очередная пара `Api`/`Impl`. Остальные модули описывают возможности приложения и не должны знать, какая конкретная реализация используется на macOS. Такой выбор делается только здесь.

## Что лежит внутри

- `Composition` создаёт инфраструктуру, общий `ProjectSession`, фабрики дочерних экранов и AppKit-адаптеры. Только эта папка импортирует чужие `Impl`-модули.
- `Navigation` показывает Home, Project или Settings через уже готовые фабрики. Она не создаёт сервисы и не вызывает сборщики других модулей.
- `Shell` хранит только состояние верхнеуровневой навигации. Редактируемый проект живёт в `ProjectSession`.
- `Adapters` реализует системные действия macOS: выбор файла, показ результата в Finder и копирование диагностики.
- `Assembly` оставляет исполняемому таргету короткий публичный вход: корневой `View`, проверку обновлений и команды меню.

Один `MacAppWorkspaceRuntime` соответствует одному окну. Он держит ровно одну сессию проекта и одну оболочку навигации; все экраны в этом окне работают с этой же сессией.

## Граница модуля

Бизнес-правила субтитров, таймлайна, Shorts, расшифровки, перевода и экспорта остаются в профильных пакетах. `MacApp` только соединяет их и добавляет macOS-специфичное поведение.

## Тесты

Проверить пакет независимо:

```bash
swift test --package-path AppTarget/Modules/Composition/MacApp
```
