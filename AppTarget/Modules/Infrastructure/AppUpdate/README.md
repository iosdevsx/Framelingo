# AppUpdate

Модуль отвечает за ручную проверку обновлений приложения через Sparkle. Он отделяет остальной код Framelingo от конкретного SDK: экрану или команде меню достаточно знать про один небольшой протокол, а детали работы Sparkle остаются внутри реализации.

## Что внутри

Пакет состоит из двух таргетов:

- `AppUpdate` — публичный контракт `AppUpdateChecking`. У него одна операция: `checkForUpdates()`.
- `AppUpdateImpl` — адаптер `SparkleAppUpdateChecker` над `SPUStandardUpdaterController` и фабрика `AppUpdateAssembly.makeChecker(...)`.

Контракт и реализация работают на `MainActor`, потому что контроллер обновлений связан с интерфейсом приложения. Параметр `startingUpdater` позволяет создать контроллер без автоматического запуска — это, в частности, используется в тесте.

## Как используется

Композиционный слой приложения получает checker через `AppUpdateAssembly`, хранит его за протоколом `AppUpdateChecking` и вызывает проверку, когда пользователь выбирает соответствующее действие. Сам модуль не решает, где находится кнопка или пункт меню, и не хранит состояние интерфейса.

Единственная внешняя зависимость — [Sparkle](https://github.com/sparkle-project/Sparkle), закреплённый на версии `2.9.4`.

## Тесты

Тесты находятся в `Tests/AppUpdateImplTests`. Сейчас они проверяют, что assembly действительно создаёт объект, соответствующий `AppUpdateChecking`, причём без запуска updater во время теста. Сетевой поиск обновлений тестами не выполняется.

```sh
swift test --package-path AppTarget/Modules/Infrastructure/AppUpdate
```
