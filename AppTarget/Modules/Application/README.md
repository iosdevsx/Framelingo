# Application

`Application` пока хранит небольшую часть состояния, которую видят разные экраны: общий индикатор расшифровки и несколько сервисов, которые ещё не вынесены из старого `AppState`.

Модуль не собирает интерфейс и не выбирает конкретные реализации сервисов. Он получает готовые зависимости извне и связывает их в прикладные сценарии.

## Что внутри

Пакет разделён на два таргета:

- `Application` — публичные типы и оставшееся общее состояние приложения;
- `ApplicationImpl` — небольшая точка сборки `ApplicationAssembly`, которая создаёт `AppState`.

Основные части:

- `AppState` — `@MainActor`-объект, за которым наблюдает интерфейс. Сейчас он публикует состояние текущей расшифровки;
- `AppStateDependencies` — явный список сервисов, нужных `AppState`;
- `TranscriptionActivity` — компактное описание фоновой расшифровки для общей панели активности.

## Связи с другими модулями

`Application` использует подготовку аудио, перевод, анализ спикеров и субтитры. Конкретные реализации выбирает `MacFeature`, поэтому здесь нет зависимости от AppKit, экранов или файловых панелей.

Логика расшифровки и перевода живёт в `TranscriptionPipeline` и `TranslationPipeline`. Планирование шортсов находится в `Shorts`, а очередь и выполнение видеоэкспорта — в `VideoExport`.

## Тесты

Тесты находятся в `Tests/ApplicationImplTests`. Экспорт здесь больше не тестируется: его API, worker и очередь проверяет пакет `VideoExport`.

Запуск тестов пакета:

```sh
swift test --package-path AppTarget/Modules/Application
```
